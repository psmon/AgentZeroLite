# M0036 수행결과 — 분할창·탭·워크스페이스

## 수행 요약

계획 Phase 4를 구현했다. 분할 트리는 직접 만든 `WorkspaceLayout<T>`(페인/분할 노드, WPF 규칙: 분할은 활성 탭을 새 이웃
페인으로 옮김, 같은 방향 부모는 흡수, 빈 페인은 부모를 접음)이고, `DockPaneNode`(탭 인덱스)와 양방향으로 매핑돼
`CliGroup.LayoutJson`에 WPF와 같은 바이트로 저장된다. 뷰는 두 층: 재귀 Grid + GridSplitter의 페인 틀/탭 스트립, 그 위의
`SurfaceHost` Canvas에 모든 렌더러를 한 번만 두고 페인의 활성 탭 컨트롤을 그 페인의 콘텐츠 사각형 위에 절대 좌표로 놓는다.
분할·이동·워크스페이스 전환에서 재부모화가 없다. 단축키는 한 표(`HotkeyTable`)를 렌더러(JS, `hotkey` 메시지)와 창
(`KeyDown` 터널링)이 같이 쓰고, `-cli layout <verb>`가 같은 명령 id를 실행한다.

### 결정·발견

- **골든 행**: 로컬 DB에 WPF가 저장한 분할 행이 없어(모두 NULL) 골든은 `DockPaneLayout.ToJson(DockPaneNode)`으로 고정했다.
  WPF `CaptureNode`가 만드는 것과 같은 객체 그래프이며 직렬화 코드가 공용이므로 바이트 동일성은 구성상 보장된다. 페인에도
  `"Vertical":false`가 쓰인다(`bool` 비-nullable) — 테스트 리터럴에 반영.
- **단축키 표**: 사용자 설정(`ShortcutSettings.Enabled`)이 있으면 그것이 제스처를 선점하고, 비어 있는 id는 WPF 설정 페이지의
  제안 표 → 호스트 기본값 순으로 채운다. macOS는 Ctrl→Cmd. `ShortcutGesture`가 키 이름을 `Pagedown`처럼 정규화하므로 비교는
  대소문자 무시.
- `-cli layout`은 WPF와 같은 `sub` 필드를 쓰고 `status`가 페인 수와 저장 JSON을 돌려준다. WindowCommandIds의 원칙
  ("모든 창 명령은 CLI로도")을 따른 것.
