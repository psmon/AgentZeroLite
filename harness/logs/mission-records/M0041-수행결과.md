# M0041 수행결과 — AgentBot UX 파리티

## 수행 요약

M0037이 AgentBot의 코어(모드 순환·액터 토폴로지·툴벨트·진행 카드·`bot-chat`/`bot-ask`)를 옮겼다면, 이번엔 표면을 채웠다.
계획 Phase 9.

UI 의존이 없는 규칙은 먼저 `ZeroCommon/Agents`로 내렸다 — `BotOptions`(지연 0–30 클램프), `ApprovalAutoResponder`
(Down×N @150ms → 100ms → Enter, 지연 후 토글 재확인), `UrlNoticeThrottle`(30초 쿨다운, 100개 초과 evict),
`TerminalTextSender`(200자 초과 → `WriteAsync`, 개행 시 Enter 추가), `KeyChordTranslator`(Ctrl+A~Z → 0x01–0x1A,
Esc → 300ms → Interrupt), `ToolTurnPresenter`(터미널 read/write → `→`/`←` 교환 뷰), `BotSessionHeader`(탭당 1회 공지).
전부 `ITerminalSession`만 의존하므로 헤드리스로 검증된다. WPF는 나중에 채택할 수 있으나 이번엔 건드리지 않았다.

뷰모델에는 옵션 바·세션 헤더·`AgentEventStream` 부착/해제·승인/URL 처리·클립보드 첨부·모드 토스트·미니 키패드를 더했고,
`ApprovalToastViewModel`(10초 카운트다운, 5분 뮤트)을 새로 만들었다. 도크는 `GridSplitter` + 크롬(분리·최대화·닫기)을 붙였고, 임베드/분리는 재부모화 대신 **뷰모델 하나에 뷰 둘**로 했다. 상태는 이미 공유 DB에 있던
`AppWindowState.IsBotDocked`를 읽고 쓴다.

### 실행 중 잡은 것

1. **`SaveWindowState`가 9개 컬럼을 전부 쓴다.** 두 호스트가 같은 행을 공유하므로 Avalonia가 이걸 불렀다면 WPF가 읽는
   `Left/Top/Width/Height/IsMaximized/LastActive*`를 덮어써서 **다음 실행 때 WPF 창이 Avalonia 창 위치로 튄다**.
   단일 컬럼만 쓰는 `SaveBotDocked`를 따로 만들고 M0041은 `SaveWindowState`를 호출하지 않는다.
2. **`OemTilde` vs `Backquote`.** `term.js`는 `e.key` 또는 `e.code`로 매칭하는데 Shift를 누르면 `e.key`가 `"~"`가 되어
   `e.code === "Backquote"`만 맞는다. `KeyName(Key.OemTilde) => "Backquote"`로 매핑하지 않으면 창 핸들러에서는 되고
   **터미널에 포커스가 있을 때만 조용히 실패** — 정작 쓰는 순간에 안 되는 버그다. `BotEmbedHotkeyTests`가 계약을 고정한다.
3. **`ShutdownMode` 미설정.** 이 호스트에 두 번째 창이 처음 생기는데 `App.axaml.cs`에 설정이 없어 기본값
   `OnLastWindowClose`였다. 플로팅 봇이 떠 있으면 메인 창을 닫아도 프로세스가 남는다 → `OnMainWindowClose` 명시.
4. **`ItemAdded` 핸들러 누수.** `AgentBotView.Attach`는 VM이 바뀔 때만 해제하므로, 분리→임베드를 N번 하면 한 메시지에
   `ScrollToEnd`가 N번 돈다. `DetachedFromVisualTree`에서 `Attach(null)`.
5. **Avalonia 12 클립보드 API 변경.** `IClipboard.GetTextAsync`는 없어졌고 `ClipboardExtensions.TryGetTextAsync`
   (`using Avalonia.Input.Platform`)이다. `ColumnDefinition`의 `x:Name`도 필드를 생성하지 않아 그리드를 이름 짓고 인덱스로 접근.
6. **`ICliGroupInfo.Tabs`가 아니라 `TabsView`** — WPF 코드를 사양으로 읽을 때 이름이 다른 지점.
7. **WPF에서 죽은 코드 3건 발견** — `chkThinking`(XAML 선언만, `.cs` 참조 0), MD 파일 첨부(필드 선언만, 읽는 곳 없음),
   웰컴 템플릿 12종(`ShowWelcomeMessage`는 한 줄만 낸다). 맞출 파리티가 없으므로 이식하지 않았다.

### 의도적 분기

- **시스템 메시지 분리.** WPF는 `AddSystemMessage` 하나가 숨김 토글에 걸리고, 그래서 "터미널 없음"까지 숨겨져
  *"음성이 고장난 것처럼 보인다"*고 `xaml.cs:1000`에 주석으로 남긴 뒤 로그로 우회했다. 여기선 `AddSystem`(잡담, 기본 숨김)과
  `AddNotice`(사용자가 봐야 하는 것, 항상 표시)로 나눴다 — WPF도 이미 "conversation data"용 우회 경로를 갖고 있다.
- **도크 위치.** WPF는 하단이지만 그 영역은 BOT/OUTPUT/LOG/NOTE 탭 스트립의 한 탭이라 스트립째 옮겨야 하고,
  무엇보다 **형제 컬럼이라야** macOS에서 터미널 네이티브 웹뷰를 가리지 않는다(DESIGN.md Phase 4 z-order 규약). 우측 유지.
- **`SetBotUiCallback`.** Avalonia는 `Chat`/`Error`를 모두 렌더한다. WPF(`MainWindow.xaml.cs:2122-2129`)는 `System`만
  보고 나머지를 버린다 — 그 버그를 파리티라는 이름으로 되따라가지 않았다.
- **네이티브 창 장식.** WPF의 커스텀 32px 타이틀바 대신 플로팅 창은 OS 장식을 쓴다(macOS 신호등 버튼과 충돌).

## 후속 수정 #1 — 봇 도크를 하단으로 (운영자 요청)

**운영자 보고**: "agentbot 이 하단에 나오게 레이아웃조정"
