# M0035 수행결과 — xterm.js WebView 터미널

## 수행 요약

계획 Phase 3을 구현했다. Windows는 `ManagedConPtyHost` 사본(`ConPtyHost`), macOS/Linux는 Porta.Pty(`PortaPtyHost`),
세션은 ZeroCommon `XtermTerminalSession`, 렌더러는 `NativeWebView` 안의 xterm.js. 자산은 `LocalAssetServer`(루프백·토큰 경로)로
서빙하고, 브리지는 `invokeCSharpAction`(JS→호스트) / `InvokeScript("window.zeroHost.recv(...)")`(호스트→JS, base64 배치)이다.
워크스페이스·탭 모델과 영속(`CliWorkspacePersistence`, WPF와 같은 행), 액터 바인딩, `-cli terminal-list/send/key/read`까지 연결했다.

### 실행 중 잡은 것

1. **ConPTY + 표준 핸들 상속** — 부모 stdio가 파이프이면(테스트 러너, `-cli`) 자식 cmd의 출력이 의사콘솔을 우회했다. WPF 원본에는
   드러나지 않던 경로. `CreateProcess` 동안 표준 핸들을 비워 해결. 진단 과정과 근거는 `DESIGN.md` 구현 기록 참조.
2. **ConPTY 종료 신호** — 파이프 EOF가 오지 않으므로 프로세스 핸들 감시 스레드를 추가(`Exited` 1회 보장).
3. **`TerminalEnvironment.PrependPath` (M0033 버그)** — `Path`/`PATH` 공존 시 열거 순서에 따라 엉뚱한 키에 붙던 간헐 실패. 정확한 `PATH` 우선.
4. `NativeWebView`는 요청 응답 합성이 없어 `LocalAssetServer`가 정본이 됐고, `BeginReparenting` API가 있어 M0036 스파이크 항목으로 기록.

## 평가

Acceptance 7항 중 Windows에서 자동으로 확인 가능한 것은 모두 통과(렌더링·`ready` 전 버퍼링·CLI read/send·종료 배너·액터 바인딩·
처리량 측정·설계 기록). **운영자 스모크가 필요한 항목**: 한글 IME, 리사이즈 추종, pwsh/Claude 탭과 Claude Code TUI, 링크 Ctrl+클릭,
막힌 탭의 Stale/Dead 배너, 입력 정지 없음. **macOS 항목**(zsh 탭, Porta 대비 체크리스트)은 CI macos-14 잡의 `PtyHostTests`·`selftest pty`가
1차 근거이고 GUI는 Mac 스모크(M0040) 때 확인한다.
