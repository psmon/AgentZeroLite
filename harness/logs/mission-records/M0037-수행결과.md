# M0037 수행결과 — AgentBot 채팅 + 에이전트 루프

## 수행 요약

계획 Phase 5를 구현했다. `AgentBotViewModel`이 WPF `AgentBotWindow`의 역할을 맡는다: CHT(활성 터미널에 `WriteAndEnter`),
KEY(입력창이 키 중계기 — 화살표·Esc·Tab·Enter·Backspace·Ctrl+C·타이핑 문자 즉시 전송), AI(`StartAgentLoop`).
액터 토폴로지는 그대로: `CreateBot` → `SetBotUiCallback`, 첫 AI 턴에 `SetAgentLoopCallbacks` + `AgentLoopBindings`
(`AgentLoopWiring` = WPF 1211–1300 이식, External 전 OS / Local은 Windows에서 모델이 로드된 경우). 툴벨트는
`WorkspaceToolHost`(WPF `WorkspaceTerminalToolHost` 이식: 터미널 4동사 + 첫 접촉 핸드셰이크, `FileToolCore`, `FileOpenPolicy`
+ OS 기본 프로그램, `HeadlessWebToolSurface`, OS 제어는 인터페이스 기본값). 진행은 한 줄의 라이브 행(Thinking/Generating 토큰 수)과
툴 카드(Acting)로, 결과는 봇 말풍선 + 타이밍 줄로 그린다. `-cli bot-chat <msg> --from X`는 DONE 봉투를 풀어 채팅에 넣고
`TerminalSentToBot`으로 봇 액터에 전달하며, `-cli bot-ask <text>`(신규)는 AI 모드로 한 턴을 시작한다(에이전트용 스모크 경로).

### 실행 중 잡은 것

1. **Gemma 4 네이티브 툴콜 문법.** 첫 E2E에서 모델이 `<|tool_call>call: list_terminals{}<tool_call|>`을 돌려줘 봉투 파서가
   "missing 'tool' field"로 두 번의 형식 교정을 소진하고 `turns=0`으로 끝났다. 같은 모델이면 WPF도 동일하게 실패하는 ZeroCommon
   문제라, `GemmaNativeToolCall.TryConvert`(네이티브 → `{"tool","args"}`)를 추가하고 `ExternalAgentLoop`가 봉투 추출 전에 한 번
   호출한다(그 외 응답은 무변경). 두 번째 E2E는 JSON을 제대로 냈지만 변환기는 그대로 유효하다.
2. **첫 AI 요청의 경쟁.** 봇 액터 부착이 비동기라 첫 `bot-ask`가 "아직 준비 안 됨"으로 끝났다. 요청을 보류했다가 부착 완료 콜백에서
   실행하도록 바꾸고, 부착 중복 호출을 `_attaching`으로 막았다.

호출이 포함된 요청("이 폴더의 README 요약해줘", "웹에서 … 검색"), Windows 로컬 LLM(LLamaSharp) 로드 후 AI 모드.
