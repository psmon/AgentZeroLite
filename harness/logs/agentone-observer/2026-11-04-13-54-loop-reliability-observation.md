# agent-one 루프 신뢰성 관찰 — 저성능 온디바이스 루프의 보강

## 실행 요약

agent-one을 **루프엔지니어 에이전트**로 강화하는 활동의 관찰 기록. 이번 관찰의 시험대(벡터)는
**소유자 승인 하의 취약점 점검 루프** — "취약점 발견 → 모의 접근 → 리포팅"을 agent-one이 스스로
반복 수행하며, 그 과정에서 드러나는 루프 결함을 포착해 소스로 되돌리는 방식이다.

- **협업 구성**: 에이전트가 **Jev(결정 엔진)** 와 협업해 매 턴 Route/Escalate/Scope/Safety를 판단.
- **사용 모델 (강조)**: agent-one이 추구하는 **자유선택 온디바이스 모델** 조합 —
  **Gemma 4 × Qwen 3.8** (everyday × reasoning, 동시성 1+1, 느린 온디바이스 HW). 상용 대형 모델이 아닌
  **저성능 로컬 모델**로도 에이전트 루프가 완주하도록 만드는 것이 이 활동의 핵심 목표.
- **관찰 대상 상세·표적 증거는 참고 위치만**: `_shared/agent-one-private-track.md` 참조
  (실제 작업/증거는 비공개 공간 `C:\code\zero-test`에만 존재, 공개 저장소에 두지 않음).

## 결과 — 저성능 루프에서 잡아낸 결함 3종 (→ 소스 반영)

| 관찰된 루프 결함 | 저성능 모델에서 왜 두드러지나 | 되돌린 개선 |
|---|---|---|
| 호출이 루프를 **영구 정지** | 느린 HW에서 서버가 keep-alive만 흘리며 토큰 0 → idle 타임아웃이 안 걸림 | idle 리셋을 `data:` 프레임으로 한정 + per-call 워치독(`maxCallSeconds`); 에스컬레이션 최종 실패 시 추론 초안 유지 |
| 출력 **잘림 → malformed JSON** | 로컬 서버 기본 max_tokens가 작아 긴 답/툴콜 JSON이 중간 절단, 멀티바이트가 깨짐 | 와이어 `max_tokens` + `MaxTokens`/`ReasoningMaxTokens` |
| **완성 산출물을 "없음"으로 오판** | 소형 모델이 하위 폴더 파일을 basename으로만 지칭 → 정확 문자열 비교 실패 → 사과·불필요 에스컬레이션·결과 폐기 | `WasWrittenThisTurn` 경로 suffix 허용 |

세 결함 모두 **스크립트 provider 헤드리스 테스트**로 재현·고정(LLM 불필요). 전체 695 통과/0 실패.
배포: `agent-one v0.8.14` (main 머지 + 태그, npm `@webnori/agent-one@0.8.14`).

## 평가

저성능 온디바이스(Gemma4×Qwen3.8)×Jev 구성에서 **보안 점검 루프가 실제로 진행**되었고(취약점 점검 →
리포트 HTML 산출까지 디스크에 생성), 바로 그 실전 루프가 **루프 결함 3종을 노출**시켜 소스 강화로
환류되었다. 저성능 모델일수록 결함이 크게 드러나므로 **루프 견고성 시험대로서 가치가 높다**(met).
남은 공백은 여전히 소형 모델의 Repeat/허위보고 경향 — 가드가 포착은 하나 발생 자체는 지속.
