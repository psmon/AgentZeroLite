# v1.12.0 — PDSA CLI (`@webnori/pdsa`) integrated into the tamer garden

**Released**: 2026-08-29
**Bump rationale**: Minor — new capability. Adds a tamer-owned knowledge doc
and tamer triggers/procedure for driving the `@webnori/pdsa` improvement-loop
CLI. No new engine (operator chose "knowledge + tamer" depth); no existing
agent/engine behavior changed beyond the tamer additions and config registration.

## Why this change

The operator installed `@webnori/pdsa` (v0.0.5) globally and asked for the
harness to *understand it and let the experts use it*. `pdsa` coaches an AI
agent through Deming's Plan→Do→Study→Act loop and accumulates each cycle into a
**per-project Kùzu graph DB** ("long-term memory for AI agents"): `plan` sets a
verifiable expected outcome, `study` has an LLM judge it (met/partial/unmet),
`act` derives the next action and can auto-link a reinforcement cycle
(`REINFORCES` edge). Recall = expectation hit-rate accumulates across runs.

Without harness integration, any agent wanting to use it would re-derive the
invocation, auth model, and — critically — risk confusing it with the harness's
**other** "PDSA" (`harness-view` dashboard's `pdsa-insight.json`, a static
log-summary). This version pins the contract and the disambiguation once.

## Integration decisions (operator-confirmed)

- **Depth = knowledge + tamer**, no dedicated engine. PDSA continuous
  improvement / retrospective is the gardener's meta domain, so tamer owns it.
- **`pdsa init` not kept.** `init` writes `.claude/skills/pdsa/SKILL.md` — a tip
  for driving the CLI as a *standalone* Claude skill. It was installed for
  reference, read, then **removed**; the harness integrates PDSA through its own
  knowledge + agent layers, not a parallel skill.
- **Repo project created**: `pdsa project set agentzero-lite` →
  `%LOCALAPPDATA%\pdsa-cli\agentzero-lite\graph.kuzu`. `pdsa check` confirmed a
  live LLM round-trip (OpenAI apikey / `gpt-5.6-terra`).

## What was added

- `harness/knowledge/tamer/pdsa-cli.md` — the contract: surface map, closed
  cycle, auth modes, graph-memory model, anti-patterns, and an explicit
  **PDSA CLI vs harness-view PDSA** comparison table.
- `harness/agents/tamer.md` — triggers (`PDSA 사이클 시작`, `PDSA 회고`,
  `개선 사이클 시작`, `run pdsa cycle`, `pdsa plan`), a "PDSA 개선 사이클"
  procedure, an optional post-mission retro note, and an "Owned convention sets"
  backlink block.

## Not in scope

If PDSA later needs several specialists to share the loop (e.g. audio +
security running parallel role-split cycles), promote it to a `pdsa-retro`
engine (Rule 2). The CLI already supports this via `--project agentzero-lite-<role>`.
