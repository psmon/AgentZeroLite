### F-2 — 한 런에 결과 하나

`ResetAgentLoopMemory` 를 Running 에서 받으면 결과를 부모에게 보내지 않고
Idle 로 돌아가, 그 `StartAgentLoop` 는 결과를 영영 못 받았다. 두 가지를 넣었다:

- reset 경로가 `FailureReason: "Reset by user"` 결과를 먼저 Tell
- 런마다 `_generation` 스탬프 → `IsStale` 이 이미 끝난 세대의 결과를 버린다
  (Idle 에도 명시적 수신자를 두어 데드레터로 새지 않게)

**회귀 테스트를 쓰다가 테스트가 먼저 틀렸다** — 두 런이 세마포어 하나를 공유해서
첫 release 가 *두 번째* 런을 끝내 버렸고, 그래서 "통과했으면 잘못된 이유로
통과"였을 테스트가 실패로 드러났다. 런마다 게이트를 분리(`BlockingLoopFactory`)
해서 고쳤고, 그 사실을 테스트 주석에 남겼다.

### F-3 — 실패를 인지하는 반복 nudge

`BuildBlockMessage` 는 이전 시도를 결과까지 인용했지만 **실패 여부를 구분하지
않았다**. `RecentAttempt.Failed` 를 추가하고 `LooksFailed` 로 판정
(`{"ok":bool,…}` 봉투 또는 최상위 `error`; 파싱 불가는 성공 취급 — 이 플래그는
문장 하나를 고를 뿐이라 오판의 비용이 결정이 아니라 어휘다).

### F-1 — 툴 결과는 데이터 (Critical)

데이터/지시 문장이 Web 섹션에만 있었다. `Hard rules` 블록 **맨 앞**으로
승격하고 출처를 명시했다(file contents / listings / terminal output / web pages).

code-coach 의 `llm-prompt-conventions` 를 먼저 읽고 맞췄다:

| 규칙 | 준수 |
|---|---|
| R-1 영어 | ✅ |
| R-2 신규 블록 ≤ ~100 토큰 | ✅ 약 60 단어 |
| R-3 hard rule 은 규칙 절 맨 위 | ✅ 테스트가 **배치까지** 검사 |

Web 섹션의 점-오브-유즈 문장은 **남겼다** — hard rules 블록은 긴 프롬프트에서
약 200줄 떨어져 있다.

## 정전 변경

- I-1 · I-3 · I-5 의 "Known …(open)" 3건 → **Resolved** 로 전환, 각 항목에
  무엇이 그것을 붙들고 있는지(테스트 이름) 명시
- **I-10 신설 — 프롬프트 예산**. F-1 을 고치며 R-2 대조 중 측정된 것:
  `AgentToolGrammar.SystemPrompt` 가 **18,089자 / 2,605단어 / 약 3,500토큰**.
  R-2 의 "800토큰 훨씬 아래" 대비 약 **4.4배**이고, 기본 `ContextSize` 2048 을
  혼자서 넘는다. F-1 이 만든 문제가 아니다(그 블록은 60단어). **감사는 측정하고
  보고할 뿐 줄이지 않는다** — Mode 1/2/3 라우팅 텍스트·트리거 목록·verb 카탈로그가
  전부 load-bearing 이라 축소는 회귀 위험이 있는 별도 과제이고, R-2 가 요구하는
  `LlmProbe` bench 비교가 함께 필요하다. 소유자는 `code-coach`.

I-10 의 검증 커맨드는 **작성 직후 실행해 2605 words 를 되돌려받는 것을 확인**했다
