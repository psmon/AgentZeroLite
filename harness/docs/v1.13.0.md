# v1.13.0 — device-smith 영입 (기기 쪽 빌드/디버그)

**날짜**: 2026-09-18
**타입**: Minor (전문가 1명 영입)
**이전**: v1.12.1

---

## 왜

AgentZero Lite 의 웨어러블 링크는 두 쪽인데, 이 저장소에는 **PC 쪽만** 있었다.
기기 펌웨어는 형제 저장소 [`psmon/Arduino`](https://github.com/psmon/Arduino) 에 있고,
링크 문제를 만날 때마다 "호스트가 이상한가, 펌웨어가 이상한가"를 가르려면 기기에 붙어야
하는데 그 방법이 이 정원 어디에도 없었다. 매번 형제 저장소의 `CLIBUILD.md` 와 각 앱
README 를 다시 읽는 비용이 반복됐다.

### 중복 책임 확인 (creator-rule Rule 5-1)

| 기존 에이전트 | 겹치나 | 판정 |
|---|---|---|
| `build-doctor` | "빌드"라는 단어만 겹침 | **아니오** — build-doctor 는 .NET 파이프라인·네이티브 DLL·버전/설치 프로그램. device-smith 는 USB·툴체인·플래시·시리얼. 도메인이 다르다 |
| 형제 저장소 `device-resource-warden` / `ble-contract-sentinel` | 기기를 다룸 | **아니오** — 그쪽은 펌웨어 *코드 리뷰*, 이쪽은 *빌드·플래시·관찰*. 정원도 다르다 |

경계는 에이전트 정의의 "하지 않는 것" 절에 못박았다. 엔진은 만들지 않았다 —
현재 단일 에이전트 작업이므로 Rule 2 의 조건(2인 이상 협업)에 해당하지 않는다.

### 트리거 중복 검사

기존 9개 에이전트 + 10개 엔진의 전체 트리거와 대조 — 충돌 없음.
`build-doctor` 의 `"빌드 점검해"` 와 신규 `"기기 빌드"` / `"펌웨어 빌드"` 는 구분된다.

## 문서 배치 — 지식 vs 제품 문서

같은 주제로 두 문서를 만든 것은 의도적이다.

| 문서 | 독자 | 성격 |
|---|---|---|
| `harness/knowledge/device-smith/…` | `device-smith` 에이전트 | 판정 기준·검증된 명령·실패 패턴. 트리거 없음 (Rule 3) |
| `Docs/wearable-device{,.kr}.md` | 사람 (README 에서 진입) | 두 저장소의 이음매, 왜 프로세스가 둘인지, 넓힐 때의 체크리스트. EN/KR 두 판이 서로를 링크 |

제품 문서가 지식 문서를 링크하고, 1차 출처는 언제나 형제 저장소라고 양쪽에 명시했다.

## 비-Arduino 확장

사용자 요구대로 기기 계열에 중립적으로 썼다. 지식 문서 §7 과 `Docs/wearable-device.md` §5 에
**새 기기를 들일 때 채울 5칸**(식별 방법 / 툴체인 진입점 / build·flash·monitor / 복구 /
실패 패턴)을 남겼다. 기기가 늘면 §3 을 기기별 파일로 분리한다.
