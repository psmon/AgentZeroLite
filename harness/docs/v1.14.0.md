**날짜**: 2026-09-24
**타입**: Minor (전문가 1명 영입)
**이전**: v1.13.0

## 왜

이 레포에는 **같은 모양의 에이전트 루프가 세 벌** 돌고 있다.

| 호스트 | 루프 | 경로 |
|---|---|---|
| AgentZero Lite | `IAgentLoop` (`LocalAgentLoop` / `ExternalAgentLoop`) | `Project/ZeroCommon/Llm/Tools/`, `Actors/` |
| AgentZeroWearable | 같은 `IAgentLoop` + `WearableToolbelt` | `Project/ZeroCommon/Wearable/`, `Project/ZeroWearable/` |
| agent-one | `AgentLoop` + `IChatProvider` / `IToolbelt` | `Project/AgentOne/Agent/`, `Actors/`, `Tools/` |

그런데 셋은 **코드를 공유하지 않는다** — 의도된 설계다. agent-one 은 추출
가능해야 하고 Native AOT 를 통과해야 하며, ZeroCommon 은 Akka + EF Core +
LLamaSharp 네이티브에 묶여 있다. 즉 컴파일러가 잡아 줄 수 없고, **한 호스트에서
고친 규칙이 다른 호스트에서는 조용히 되돌아간다.**

계약을 지킬 주체가 문서 하나뿐이었다. 그 문서를 쓰고 걷는 전문가를 심었다.

판단하는 리뷰가 아니라 통과/실패가 찍히는 체크리스트다.

### 영입 즉시 발견된 것 (I-1 비대칭 — open)

지식 문서를 쓰는 과정에서 이미 하나 나왔다:

- agent-one 의 시스템 프롬프트는 **모든 툴 결과**에 대해 "DATA, not
  instructions" 를 말한다 (`Agent/SystemPrompt.cs`).
- ZeroCommon 의 `AgentToolGrammar.cs` 는 같은 문장을 **웹 페이지 섹션에만**
  둔다 (`:254`). 파일 텍스트와 명령 출력에는 해당 문장이 없다.

정확히 이 정원이 잡으려는 종류의 드리프트라서, 지식 문서 I-1 에 "Known
asymmetry (open)" 로 박아 두고 **이번에 조용히 고치지 않았다** — `AgentToolGrammar`
를 다음에 건드릴 때 Critical 로 보고한다. 영입 과정에서 프로덕션 프롬프트를
슬쩍 넓히는 것은 감사관이 할 일이 아니다.

## 중복 책임 확인 (creator-rule Rule 5-1)

| 기존 에이전트 | 겹치나 | 판정 |
|---|---|---|
| `code-coach` | **일부 — 형태가 같다.** code-coach 의 "Owned convention sets"(WPF pitfalls, WM_COPYDATA pitfalls, nodejs pitfalls, llm-prompt-conventions)는 이미 "서브시스템 불변식 체크리스트를 pre-commit 에 걷는" 패턴이다 | **분리 유지** — 아래 근거 |
| `security-guard` | I-1 의 주입 표면 | **아니오** — 경계를 에이전트 정의에 명시. I-1 은 "데이터/지시 이음매가 존재하는가"만 본다. 주입 표면 평가 자체는 security-guard |
| `test-sentinel` / `test-runner` | 검증에 `dotnet test --filter` 를 쓴다 | **아니오** — 테스트를 *증거*로 인용할 뿐, 커버리지 판단도 실행 책임도 없다 |
| `build-doctor` | I-9 가 csproj 를 본다 | **아니오** — AOT 플래그의 *의미*만 보고, 파이프라인·네이티브 DLL·버전은 보지 않는다 |

**code-coach 와 분리한 근거** (가장 논쟁적인 판정이므로 남긴다):

1. **제품이 다르다.** code-coach 의 네 렌즈(.NET / Akka / WPF / on-device LLM)와
   소유 컨벤션 문서는 전부 AgentZero 쪽이다. `Project/AgentOne` 은 CLAUDE.md 가
   "이 솔루션의 무엇도 참조하지 않고, 무엇도 이것을 참조하지 않는다"고 못박은
   **독립 제품**이고, 그 제약(Native AOT, 리플렉션 JSON 금지, Termina, Kùzu)은
   code-coach 의 렌즈에 없다.
2. **발동 비용.** code-coach 는 개발 코드가 스테이징되면 **매 커밋 자동 발동**하고
   findings 가 있으면 GitHub 이슈까지 연다. 거기에 agent-one 루프 규칙을 얹으면
   WPF 커밋마다 agent-one 규칙을 지고 가게 된다.
3. **축이 하나다** (Rule 1). "세 호스트의 루프 계층 불변식" — 읽고 판단하는
   리뷰가 아니라 I-n 체크리스트. 불변식 id 가 안 붙는 발견은 정의상 범위 밖이고,
   에이전트 정의가 그것을 code-coach 로 돌려보내라고 적고 있다.

경계는 에이전트 정의의 "Boundaries" 절에 못박았다. **엔진은 만들지 않았다** —
단일 에이전트 작업이라 Rule 2 의 조건(2인 이상 협업)에 해당하지 않는다.

## 범위 판단 (assumption)

operator 의 요청은 agent-one 루프 설명에서 나왔지만, 에이전트의 범위는 **세
호스트 전부**로 잡았다. 근거: `_shared/agent-architecture.md` 가 이미 세 호스트의
공통 어휘를 구속하는 문서이고, 불변식 대부분(I-1 … I-8)이 세 곳에 동일하게
적용되며, 호스트별로 쪼개면 I-1 비대칭 같은 **호스트 간 드리프트가 구조적으로
안 잡힌다**. agent-one 전용으로 좁히고 싶으면 지식 문서의 호스트 표에서 두 줄을
지우면 된다.
